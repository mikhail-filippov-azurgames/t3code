# Выбор исполнителя

Исполнителя выбирает сервер, а не агент. Ведущий указывает для участника команды роль и уровень задачи; сервер по этой таблице находит модель и запускает её.

Правила поведения задаются документами ролей. Здесь задаётся выбор модели.

## 1. Клетки: роль × уровень

В клетке — кандидаты в порядке проверки. Работает первый доступный.

| Роль | low | medium | high | very-high |
|---|---|---|---|---|
| `architect`, `architect-*` | O → S → KP → W → U → N → D → E → L | O → S → KP → W → U → N → D → E → L | O → S → KP → W → U → N → E → L → D → K | O → S → KP → W → U → N → E → L → D |
| `implementation` | D → E → L → U | E → L → D → U | U → E → L → D → K → S | K → W → KP → S → U → E → L → D |
| `review-*` | S → D → E → L → U | S → D → E → L → U | KP → E → L → U → D → K → S | KP → W → S → U → E → L → D |
| `test` | D → E → L → U | E → L → D → U | U → E → L → D → K → S | K → W → KP → S → U → E → L → D |
| `research` | D → E → L → U | D → E → L → U | E → L → U → D → K → S | E → L → W → KP → S → U → D |
| `general` | D → E → L → U | D → E → L → U | E → L → U → D → K → S | E → L → W → KP → S → U → D |
| `planner` | O@low → S@low → KP@low | O@low → S@low → KP@low | O@low → S@low → KP@low | O@low → S@low → KP@low |

`alias@level` в клетке фиксирует уровень модели: `planner` всегда идёт на `low`, независимо от уровня задачи.

Ведущий (`lead`) в таблицу не входит: человек начинает чат с той моделью, которую назначает ведущим.

## 3. Алгоритм сервера

1. Вход: роль (со специализацией) и уровень `low | medium | high | very-high` из состава команды.
2. Клетка = строка роли × столбец уровня. Специализация на выбор клетки не влияет: `review-contracts` берёт строку `review-*`.
3. Для каждого кандидата клетки по порядку: проверить по живому каталогу, что модель есть, провайдер включён, options из §2 поддерживаются. Первый годный запускается с options из §2 для этого уровня и режимом обслуживания из §5.
4. Годных нет: участник не создаётся, ведущему уходит письмо `system → lead` с клеткой, кандидатами и причинами отказа.
5. После запуска замена запрещена. Сбой, таймаут или неясный результат — письмо ведущему. Новая попытка — только по решению ведущего.
6. Сервер записывает: ревизию таблицы, клетку, рассмотренных кандидатов с причинами, запущенную модель и options.
7. Таблица с алиасом, которого нет в §2, считается битой: сервер её не загружает и сообщает об ошибке.

## 4. Выбор уровня

Уровень задаёт ведущий в составе команды, по своей оценке сложности задачи. Для `implementation` по умолчанию — уровень сессии ведущего; всё выше `very-high` считается `very-high`.

## 5. Режим обслуживания

Для всех провайдеров и моделей используется только обычный (медленный) режим обслуживания. Никогда не выбираются fast mode, priority/flex-upgraded tier, «super speed» и любые другие ускоренные опции: они стоят в 2–4 раза больше токенов. Для целей §2 это значит: Codex всегда получает `serviceTier=default`, Claude — `fastMode=false`; ускоренное значение не передаётся, даже если каталог предлагает его по умолчанию.

Переопределить это может только человек — явно и на одну задачу. Переопределение записывается в evidence делегации вместе с задачей, для которой оно дано.
